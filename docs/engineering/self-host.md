# Offline self-host installation qualification

The supported installation path is the provisioned Linux arm64 Docker package in [deploy/selfhost](../../deploy/selfhost/README.md). One controller installs the private workspace, migrates its database, starts its CPU worker, checks HTTPS readiness and manages paired backup/restore, upgrade and data-retaining uninstall. Installation consumes verified local images rather than assembling development services or downloading dependencies. Initial identity is private and the initial workspace contains no models or manufactured training evidence.

## Tested feature matrix

Measured 24 October 2026 on an Apple M5 Pro Mac, macOS 27.0.1, 48 GiB physical memory, Docker Desktop engine 29.8.2 with an 8 GiB Linux VM (`MemTotal:8317267968`), Linux 7.0.14-linuxkit, native arm64. The host controller ran with Python 3.12.15; the installed Mac launcher executable also ran with system Python 3.9.6. The runtime image uses pinned Python 3.12.15, the 41-package Linux arm64 Python lock, the frontend package lock and exact Python/Node/Caddy/PostgreSQL image digests.

The small reference proves installation and real numerical/data execution. It does not establish useful language accuracy, pretrained fine-tuning quality or production capacity. The API/worker/reconciler are non-root, read-only containers with one CPU and 1 GiB caps each; PostgreSQL is capped at 512 MiB and Caddy at 256 MiB. The package requires at least 4 GiB assigned to its local Linux arm64 Docker engine. Those limits do not reserve host free memory or qualify concurrent heavy workloads. Run one controller maintenance operation at a time per instance.

The controller deliberately uses a reviewed local Unix-socket Docker engine and only exposes the installed Compose binary to an otherwise isolated Docker configuration. Host registry credentials and `DOCKER_HOST` overrides are not forwarded. Instance secrets, raw operation diagnostics and backups stay in private directories; public diagnostic receipts and curated evidence omit credentials and database dumps.

## Reproduction and exact artifacts

The committed builder requires a clean source checkout and never overwrites its output or an existing release tag. It verifies the installed Python dependency resolution and records immutable built image IDs plus every shipped file's checksum. The runtime package's release manifest records its actual executable source commit; subsequent documentation/evidence commits do not relabel that build.

Use the build/install/qualification commands in the [package guide](../../deploy/selfhost/README.md). `scripts/qualify_selfhost.py` runs the fresh-instance lifecycle with an optional distinct upgrade release. Its default cleanup is restricted to its own newly generated synthetic projects and volumes. Signed distribution, clean native OS installers, real remote customer environments and broad hardware/model qualification are explicit follow-on gates.

Curated measured receipts, package manifests, tensor comparisons, UI images and regression results are retained in [the TASK-34 evidence directory](verification/task34-selfhost-2026-10-24/). Private owner credentials, session/API keys, `.env` files, raw backups and operation logs are excluded.
