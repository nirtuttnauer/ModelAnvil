## Corrections

- Supported text Safetensors imports now compare all tensor names/shapes with a bounded metadata-only model. Missing tensors, incompatible shapes and repeated shard tensors refuse before candidate creation. Tied-weight aliases are accepted. Unsupported/quantized/adapter formats retain an explicit structural-only boundary and still require their own runtime load checks.
- GGUF previously accepted a valid eight-byte header without parsing its contents. It now uses the optional pinned `gguf==0.19.0` reader in a separate process with a 20-second deadline. It checks bounded metadata/tensor counts, complete nonoverlapping tensor payloads and actual embedded vocabulary/template metadata. Its tokenizer digest includes the complete GGUF artifact reference. Structural validity does not assert architecture loadability; imported candidates remain draft.
- The public weight transfer encountered `us.aws.cdn.hf.co`, absent from the old exact-origin default. The current [Hugging Face download documentation](https://huggingface.co/docs/hub/models-downloading) identifies this CDN and `us.gcp.cdn.hf.co`; both exact HTTPS origins are now in the installation default. Custom installation lists and existing project policies retain their restrictions and require explicit origin approval. Unknown destinations, content upload and cross-origin credential forwarding remain blocked.
- New import jobs retain their owning project. Inspection exposes current runtime action eligibility and the browser shows file byte sizes. Import status and job links remain visually separate.

GGUF parser usage follows the upstream [reader implementation](https://github.com/ggml-org/llama.cpp/blob/master/gguf-py/gguf/gguf_reader.py). Parser output is limited to structural receipts; failures do not echo source metadata, signed download URLs or credentials.
