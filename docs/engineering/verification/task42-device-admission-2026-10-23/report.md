# TASK-42 attempt-bound local GPU admission

23 October 2026. GPU jobs previously enforced one worker slot and an execution-time POSIX device lock, but workers in separate pools could claim the same physical device concurrently. The claim protocol now takes one internal database reservation per cooperating host/account/device and binds it to the fenced attempt. Physical coordination spans tenant namespaces without exposing another tenant's attempt through a public API. MPS and MLX share the Apple device key. This is single-host coordination using a common database and private lock root; remote hosts, other OS accounts/apps and device groups remain outside this implementation envelope.

Before a GPU claim reserves a worker slot or creates an attempt, it verifies the exact tenant-scoped training run, project, worker, runtime contract/build, installed packages, fresh device/host/framework identity, current capacity and authorized unexpired step reservation. Changed placement, vanished devices, false capabilities, changed budget policy and unknown capacity refuse. Discrete devices require an actual hardware UUID. New training jobs retain their owning project. Runtime build pins cover the admission and claim implementations.

Live memory observation is separate from immutable placement identity: a changed free-byte count or timestamp does not invalidate an otherwise current preview by itself, while inadequate/unknown headroom blocks approval. Discrete GPU admission requires framework-reported free memory; MPS uses its documented process allowance including driver/cache allocations, and MLX uses its process working-set allowance. These process allowances are explicitly not system-wide free memory. Preflight exposes selected backend/device, headroom, units, observation time and scope.

The database device reservation is released on committed completion/cancellation or lease reconciliation, matching the owning attempt ID so an old result cannot release a newer owner's reservation. The existing POSIX execution lock remains held through actual allocation cleanup, including a child process that outlives its parent. An expired process still holding a device blocks a new physical allocation. Execution renews its fence and repeats placement/headroom checks after acquiring the process lock and immediately before model allocation. Existing checkpoint and usage fences continue rejecting duplicate/stale commits.

The GPU runtime admission contract changes to `attempt_db_and_posix_user_host_v2`. Refresh the trusted local worker/runner registration and run a new preview for this contract; old GPU placement/build pins cannot authorize new work. Historical checkpoints and evidence remain retained. This change does not requalify a GPU or upgrade an older hardware report.
