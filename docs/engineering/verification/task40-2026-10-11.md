# TASK-40 Apple GPU implementation review — 11 October 2026

The current Apple M5 Pro now runs the pinned SmolLM2-135M FP32 training recipe and independent MPS inference, with CPU-readable Safetensors checkpoints. A fresh physical pilot checked device placement, unified-memory process headroom, checkpoint recovery, cancellation, corrupt-input settlement and unsupported option rejection. The developer also requested a local host: **ModelAnvil GPU** was created in **Default Organization**, dedicated worker ID **1** was registered, its preflight passed, and its polling process was started. TASK-40 is ready for developer review within this measured envelope.

## What changed

- `hf_runtime.py` checks MPS recommended working set and current driver allocations, requires 4 GiB remaining process allowance and caps allocations at 90% of the recommendation. Each committed step records unified-memory observations. This does not reserve global GPU memory.
- Both preflight and launch reject non-FP32 training, adapters and quantization before creating jobs or reserving budget. The fixed recipe remains full SFT.
- `hf_candidate_infer.py` independently loads complete finite candidate tensors, explicitly selects CPU/MPS/CUDA/ROCm/XPU, verifies parameter/output residency, records memory/timing and hashes all five model/tokenizer files. CUDA/HIP identity and unavailable/unknown-capacity devices fail closed.
- The physical qualification script now asserts unsupported options allocate nothing and compares independent CPU and selected-GPU greedy output for the same candidate.
- Training UI labels accommodate GPU workers, expose actual training precision and observed device/capacity source, and use the estimate's units. GPU time and currency remain unknown. The server inference button still correctly describes its CPU execution.
- Persistent `.venv-gpu`, pinned local model files and main-database registration were prepared at the developer's request. [Host instructions](../apple-gpu-host.md) cover startup, project selection and limits.

## Bounds and remaining work

This is a three-step correctness fixture on one M5 Pro, not a model-quality/throughput benchmark or production release qualification. No other Apple generation was tested. Full-range workload stress, other models, MLX, mixed precision, LoRA/QLoRA, quantization, multi-GPU and remote workers are outside this recipe. The OS-bundled driver version cannot be separated from the observed OS. Exported candidate metadata references immutable files; the independent consumer requires those five files materialized locally.

GPU capacity remains an observation. Cross-pool device reservations/admission are TASK-42 and require its dependency gate; checkpoint retention/orphan cleanup also remains operator work. The worker is a foreground poller and needs restart after exit/reboot. Production qualification flags remain false. Only the developer accepts the outcome.
