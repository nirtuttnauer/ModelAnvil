# TASK-36 review — accelerator foundation

Developer instruction: “i would like to add also gpu support of all kinds”, followed
by “Add tasks and start implementation” on 11 October 2026. Aftur records that exact
implementation approval for TASK-36–TASK-42. TASK-36 was claimed by codex before
editing; this report requests review and does not record developer acceptance.

## Delivered

- `modelanvil/accelerators.py`: optional-PyTorch, Django-independent JSON inventory,
  explicit device selection, memory checks and bounded FP32 forward/backward/SGD
  diagnostics for CUDA, ROCm, XPU and MPS. AMD HIP retains its backend identity
  despite using the framework CUDA namespace. Probe failures and incomplete
  enumeration reject selection with corrective actions; no CPU fallback is chosen.
- `modelanvil/test_accelerators.py`: cross-vendor detection/selection fixtures,
  missing/broken runtimes, partial device enumeration, memory and index failures,
  CLI error JSON, diagnostic bounds, kernel errors and MPS fallback rejection.
- `docs/engineering/accelerators.md` and README: CLI usage, optional runtime setup,
  memory semantics, process-local identifiers and qualification boundaries.

No changes to the independently owned TASK-13 training runtime, existing worker
registration/admission, database, budget or browser launch behavior. PyTorch was
installed only in `/private/tmp/modelanvil-gpu-venv`, not the control-plane environment.

## Remaining work and limits

NVIDIA, AMD and Intel are covered by unit fixtures, not physical-device reports.
The bounded Apple primitive is not a trained transformer or a checkpoint-loading
qualification. Apple recommended unified-memory budget is not dedicated VRAM and
does not satisfy a requested measured device-memory threshold. Free-memory checks,
exclusive reservations and server admission belong to TASK-42. Driver versions,
precision, quantization, adapters, export and model-specific support need backend
reports in TASK-37–TASK-40; portable Vulkan inference is TASK-41. Multi-GPU remains
TASK-17. No model/operation is newly declared production supported.

The full application test suite and web build were not rerun for this isolated
module/CLI change. TASK-5's earlier full run recorded an unrelated TASK-13 test
failure; this work does not resolve or reclassify that result. The checkout is
`main` with no baseline commit and all files untracked, so no commit or PR is
claimed. Evidence binds these source files by SHA-256.
