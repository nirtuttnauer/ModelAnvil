23 October 2026. The versioned visual/list recipe implementation now accepts verified CPU reference bundles alongside pretrained local snapshots, freezes registered model/tokenizer identity, and checks current model access before checkpoints and publication. ## Detector regression found by the run

The first authored prompts were correctly rejected as too short before loading a model. The longer fixture then exposed a detector defect: a single eight-character string matched a “repeated unit” because the detector accepted one copy. The shared detector now requires at least three copies, matching its documented rule. Tests retain single-character/repeated-unit refusal and cover one unit, two copies and three copies. Minimum-length and privacy checks remain enforced. Earlier refusals and the failed harness receipts are retained in private task evidence.

## Validation and qualification boundary

The complete integrated backend passed 1,093 tests in 176 seconds with 11 optional environment skips. Forty focused detector/recipe checks passed. All 228 frontend tests, production build and Storybook build passed; migration consistency and whitespace checks passed. New tests cover actual reference-model generation, runtime failure versus row rejection and changed-model output withheld before checkpoint. Existing tests cover protected groups before model loading, immutable versions, typed dependencies, malformed data, preview binding/review gates, checkpoint corruption, recovery, quota settlement and publication fencing. [Source hashes](source-sha256.json) identify the verified implementation.

This release qualifies bounded local CPU execution. It does not establish representative generated-data quality, non-Mac accelerators, remote recipe providers, larger streaming recipes or production capacity. Generated rows retain `review_required` provenance; publication does not certify model quality. Limits remain 2–12 typed steps, 1–4 sources, 16 MiB/256 source records, three preview rows per transform, 32 generation rows per step, 64 calls per attempt, 256 requested output tokens and three reserved attempt units. Actual model context/output limits can be smaller and overflow fails without silent truncation. Completed-call usage excludes unfinished interrupted calls whose usage cannot be reconstructed. Required CI must pass on the exact PR head before merge.
